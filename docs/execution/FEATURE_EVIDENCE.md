## Gate coverage and overlap

`cargo xtask verify` is twelve stages: Rust formatting (including fuzz manifest), Clippy with warnings denied, production build, tests, deterministic coverage, generated artifacts, example matrix/execution, documentation consistency, supply-chain/security checks, package installation, and production-boundary checks. Read its current implementation before scheduling because subcommands deliberately overlap. `acceptance` packages the binary and runs forty-six numbered scenarios; `completeness` packages and executes a cross-feature durable composite. `examples-verify` builds the CLI, validates the exact Markdown inventory, checks v1 examples, executes ten named v1 workflows plus preview/denial paths, checks documentation examples, and checks Markdown links. A checked YAML is not executed evidence.

The live OpenAI example gate expects exactly seven existing workflow paths and includes local and container repair continuations; `acceptance-live-openai` also includes a real container invocation. `resource-budget-live-openai` intentionally fails the second provider request after one successful response. Ordinary CI must stay credential-free. Live request/token/cost/time accounting and exact source/build/image relationships must be retained in the execution ledger, including failed paid attempts.

## Missing task-specific evidence at the inventory checkpoint

The task requires twenty separate useful DevOps workflows with clean-directory deterministic execution, live variants for genuinely different agent workflows, semantic artifact assertions, permissions, fixture identities, cleanup, and a machine-readable catalog. Existing generic examples and mock protocol fixtures are useful foundations but do not prove those twenty requested use cases. The new catalog must connect each workflow to an executed result and must be part of the exact-inventory gate.

Hostile instruction text remains untrusted content; guarantees must be stated in observable terms: denied filesystem/process/network effects do not occur, tools remain allowlisted, and model output cannot enlarge graph or authority. A test that merely asks a model to ignore malicious text is not a deterministic governance proof.
