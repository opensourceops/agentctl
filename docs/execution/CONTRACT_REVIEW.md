## Existing contract and decisions

`AgentDefinition.instructionsFile` already exists in `crates/agentctl-core/src/dsl.rs:162`; validation at line 1755 requires exactly one of `instructions` and `instructionsFile`. Preserve that syntax and exclusivity. At runtime, instruction files are workspace-policy resolved, read with a 1 MiB bound and UTF-8 decoding, recorded as an `agent.instructions.read` observation effect, and included in task recovery fingerprints. The recorded successful read is preferred when reconstructing a source fingerprint.

`run` already uses the workflow's parent as its default base (`crates/agentctl-cli/src/main.rs:1051`), independent of the invoking directory when the workflow path is absolute. `--workspace` changes that base. The `policy.workspaceRoot` is resolved from the selected base, and instruction paths currently resolve from this workspace root. `resume` and `fork` recover the persisted base unless explicitly overridden. `replay` loads persisted workflow/plan/tasks/effects and builds no provider registry; it does not compile a user workflow or reread instruction files. “Keyless” means no provider credential; an explicitly encrypted database still needs its decryption key.

Existing variable precedence is shallow top-level key replacement, with agent defaults followed by task vars. Workflow invocation input defaults, `--inputs-file`/`--inputs`, and repeated `--input` are a separate `inputs` namespace. Repeated `--input` keys use the last flag. Inline and file agent instructions are currently literal strings rather than rendered templates, even though task input/vars use the template engine.

The proposed additive contract below must be recorded before implementation and verified against the final code. New `varsFiles` entries are ordered left-to-right, and the later source replaces an entire top-level key; objects are not implicitly deep-merged.

| Namespace | Low → high precedence | Compatibility rule |
|---|---|---|
| `vars` | workflow `varsFiles` → workflow `vars` → agent `varsFiles` → agent `vars` → task `varsFiles` → task `vars` → repeated invocation `--vars-file` → repeated invocation `--var` | Existing agent/task outcomes remain identical when new sources are absent. Invocation var flags are new and explicitly override task-local values. |
| `inputs` | workflow input defaults → one `--inputs-file` or `--inputs` object → repeated `--input` | Keep existing flags and typing; `${{ inputs.name }}` explicitly accesses this namespace. |
| engine bindings | generated foreach/matrix/loop bindings | User files/inline/invocation values may not replace reserved engine bindings. |
| environment/secrets | no implicit variable import | Only existing policy-gated dedicated secret references resolve secrets at adapter boundaries. |

Arrays, objects, scalars and explicit null replace the previous value as a whole. Missing keys preserve lower-priority values. Duplicate YAML mapping keys, recursive includes, non-mapping variable documents, unsafe paths, nonregular files, invalid UTF-8 and oversized files must be rejected. Ordinary variable sources convey data, never policy grants or process environment access. Diagnostics may identify a key, source path and winning precedence without printing values.

## Confirmed gaps and recommended fixes

1. **Instruction bytes are not part of check/plan.** `load_and_compile` (`cli/src/main.rs:2560`) only parses workflow YAML and packs. The compiler checks templates in task inputs/vars (`core/src/compiler.rs:2248`), not inline/file agent instructions. A missing or hostile file can remain undiscovered until runtime. Resolve and capture file sources before compilation, retain the digest in the plan/workflow identity and validate instructions through the same template grammar and task dependency rules. Add CLI tests that missing/invalid sources fail before database creation, independent of shell cwd.

2. **Multiple mutable reads create inconsistent reviewed/executed identity.** Runtime execution metadata fingerprints read file content (`runtime/src/lib.rs:3783,4274` calling line 7685), then `execute_agent` rereads it at line 6362. A change between reads can make the stored definition fingerprint describe different bytes from the provider request. Later completion sometimes recomputes using recorded effects, but the approval/dispatch window still lacks one authoritative capture. Persist one immutable validated snapshot before planning, and use it for compilation, approval identities, provider requests and recovery. Add a test that modifies/deletes the source between compile, approval and resume, then asserts the reviewed snapshot is dispatched and the provider call count is bounded.

3. **Resume still resolves a path before using recorded content.** At line 6334, `policy.resolve_read_path(path)` runs before `prepare_effect` returns a recorded successful read. Removing the mutable source after a successful read can block a paused run even though the necessary content is durable. The fresh execution metadata fingerprint can likewise reread the path before resume dispatch. Snapshot-backed execution should not require the file after run creation; add pause/read/model-approval/resume tests with the source deleted.

4. **Pack origins and assets are not retained.** `load_packs` (`cli/src/main.rs:2688`) qualifies agent tools and workflow task names, then inserts definitions, but does not carry the manifest origin into instruction resolution. The pack resolver fetches a manifest rather than establishing a materialized origin for arbitrary external assets. A packed agent's `instructionsFile` can resolve to unrelated caller workspace content. Keep a source-origin map per imported definition and verify included assets against pack integrity/trust. For sources that cannot supply verified local assets, fail with an actionable supported-source error; do not silently fall back to caller files. Add local/Git/archive pack tests for content replacement, tamper, missing asset and traversal.

5. **Instruction files lack an explicit regular-file and race-safe read contract.** `read_bounded_text_sync` (line 8283) and async equivalent (line 8969) open then read without checking metadata is a regular file. A FIFO can block despite byte bounds. Policy canonicalization precedes open, leaving a symlink-replacement race. Capture through an opened descriptor with regular-file/type/UTF-8/size checks, containment revalidation and a documented supported trust boundary. Test directories, FIFO where supported, oversized file, invalid UTF-8, denied root, symlink escape, missing/unreadable file and a replaced path. Do not call a bounded byte count a timeout guarantee.

6. **Agent instructions do not render templates.** Provider requests at runtime line 6438 use the literal `instructions` value. To make file templates coherent, render both exclusive sources in the same typed task context before provider dispatch. Missing values and object interpolation must fail identically to task templates; a dependency reference must appear in `needs`. Sub-workflow local inputs need the same namespaced rewrite that child task inputs receive. Add a capturing fake provider that verifies the actual `ProviderRequest.instructions`, not only final prose.

7. **Ordered variable files and origin diagnostics are absent.** `WorkflowSpec` contains no workflow vars or var-file field; `AgentDefinition`/tasks expose only inline vars. Compiler line 1219 merges agent vars and task vars. Introduce a common source resolver, preserve the precedence table, reject engine-binding collisions across every source and ensure resolved winning vars enter task fingerprints without invalidating unrelated boundaries. Test repeated flags/files, each replacement type, nested duplicate keys, templates, no process environment import, secret-shaped values, pack/sub-workflow sources, recovery and redacted origin output.

8. **Live suite budgets are not shared or fully reserved.** The runtime has atomic per-run resource budgets, but `xtask/src/acceptance.rs:4876` checks a command-local 40-request/$10 estimate after completed runs. `reserve_live_requests` only checks request counts and is used selectively; there is no shared 200,000-token/30-minute ledger across live commands/retries. `live_openai` runs the local paid workflow before probing the container engine at line 3653 and does not call the guard. Add a shared durable suite allowance/reservation boundary, conservatively reserve every planned turn/token ceiling before subprocess launch, reconcile actual usage and retain failed-attempt accounting. Probe Docker/Podman before any paid command that later requires it. Explicit current pricing or honest unresolved monetary accounting is required.

9. **Doctor reports partial availability as readiness.** The carried change at `cli/src/main.rs:2597` labels file/process credentials available without checking them, examines every declared provider rather than only reachable requirements, and considers any Docker/Podman file on PATH sufficient. Reuse non-dispatching registry/preflight checks where appropriate, make the scope of each result explicit and avoid asserting engine usability or model access from a path/credential-presence check. Add absent/nonexecutable engine, explicit engine mismatch, unused provider, missing mounted secret and invalid helper tests.

10. **Example/documentation inventory overstates execution.** `examples/v1/README.md` says only `providers smoke-openai --live` is used for release testing, contradicting README, xtask and later evidence. `verify_examples` statically checks most v1 YAML and executes a fixed ten-workflow subset. The live matrix has exactly seven expected paths, including the source/repair pair; adding new examples without updating it will fail or escape execution depending on the gate. Replace contradictory prose, distinguish static/mock/live/real-container evidence and hook the requested twenty-workflow catalog into exact inventory plus semantic execution.

## Implementation checkpoint after this audit

The source-capture increment implements gaps 1–3 and 5–7 through `core/src/sources.rs`, DSL/compiler fields and runtime snapshot consumption. It preserves exclusive instruction sources, adds the eight-layer variable contract, per-layer and effective per-task origin diagnostics, immutable UTF-8 snapshots, pack digest checks on captured bytes, descriptor-based Unix no-follow reads, regular-file/byte/reference bounds, explicit read-policy denial, engine-binding checks, instruction template validation/namespacing, and rendered-instruction reuse identity. Repeated references share one captured file value. Ordinary `{env: ...}` or `{file: ...}` variable objects remain inert data for compatibility; there is no implicit credential or environment dereference.

Runtime `start` captures legacy embedded file-backed definitions before run creation; CLI workflows capture before compilation. Fresh captured runs retain instruction/variable bytes across read approval, model approval, source replacement/deletion, resume, replay and explicit fresh fork. Old snapshotless persisted histories remain a legacy compatibility boundary: successful recorded observation effects can be reused, but missing never-captured source inputs cannot be invented. Unix no-follow descriptor traversal prevents pathname symlink replacement from changing an opened source. This is configuration capture within the documented trusted local-process boundary, not a new whole-workflow OS sandbox.

Validation on the working source: eight focused source tests and four focused runtime instruction tests passed. The broader `cargo test -p agentctl-core -p agentctl-runtime --locked` then passed 72 core unit tests, one compatibility test and 96 runtime tests; one existing real-container test remained explicitly ignored because it requires a usable engine and repository-built image. The parent execution ledger must record the separate real-container gate, final source SHA and later full release result. A compiler diagnostic-order regression introduced during this increment was fixed and rerun; it is not a baseline defect.

The runtime input-token reservation now uses serialized UTF-8 bytes plus a 256-token framing allowance instead of dividing bytes by four. This deliberately over-reserves compared with typical English tokenization and addresses under-reservation for high-entropy/non-English text. Actual provider usage remains reconciled. The controlled actual-overrun fixture now reserves a 5,000-input-token limit and reports 6,000 mock input tokens so it still exercises a post-response breach rather than stopping before dispatch. No provider cost/performance improvement is claimed.

Gap 4's manifest/source origin plumbing, gaps 8–10, generated artifacts, examples, documentation-site changes and final release gates are integrated by the parent task. These are not marked passed by this implementation checkpoint.
